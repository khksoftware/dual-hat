# Canonical Entrypoints

This contract answers: where do I begin?

| Task | Required first authority |
| --- | --- |
| First use or product onboarding | root README, onboarding workflow, installation/binding guide, then generated approval package |
| New architecture work | architecture authority, decisions index, requirements |
| Capability implementation | active session, roadmap, work order, owning domain, conformance |
| Repository migration | repository blueprint, lifecycle policy, consumers/writers, scan plan |
| Validation or incident | validation protocol, owning subsystem, current evidence/telemetry |
| Phase/release closure | phase plan, exit criteria, health/debt, publication/closure |
| External publication | source map, prior marker, drift, licensing, standalone profile |
| Context refresh | context/retrieval protocol and current handover pair |
| Development model selection | abstract model-tier policy, then local adapter binding evidence |
| Production model selection | explicit user-approved production configuration; never development detection |
| Continuity closeout | sealed work order, continuity-closeout policy, trigger decision, deferred-publication inventory |

Product profiles bind these roles to concrete current paths. Entrypoints distinguish current authority, generated projections, archives, and superseded paths, and cross-check against the domain index.
