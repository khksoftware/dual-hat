# Dual Hat 1.1.0 Release Notes

Dual Hat 1.1.0 is the accumulated backward-compatible feature release after 1.0.1. It combines systemic review and execution-integrity controls with plan-first repository/product onboarding, environment-adaptive model governance, and continuity/full-close publication behavior.

## What is new

- Onboarding for no repository, empty or nearly empty repositories, and existing projects.
- Quick, Standard, and Deep discovery with product purpose, users, protected characteristics, constraints, architecture clues, risks, and proposed-not-accepted debt.
- No product mutation before an exact authority-bound onboarding approval.
- External framework installation and bounded pinned project-local binding, including update, rollback, removal, and re-onboarding.
- Integrated and Split operation with safe, resumable mode transitions.
- Four provider-neutral model tiers, evidence-backed development-environment mapping, explicit production provider/model configuration, manual host fallback, atomic switching, and mandatory-tier hard stops.
- Initial work estimates and governed revisions after material change.
- Lightweight continuity and enumerated full-closure triggers, plus deferred/batched publication inventories.
- Persistent user quality rules, precedence, tier-aware suppression, effective-plan hashing, finding closure, pending preliminary baselines, and direction-aware non-regression comparison.
- Conditional Architecture review at Light, Standard, and Deep tiers, independent Deep review, and analogous-gap evidence.
- Strengthened work-order authorization, canonical containment, rights/readiness checks, retrieval boundaries, binary/secret inspection, committed-tree provenance, exact release sets, and transactional replacement with verified rollback.
- Local-first semantic fixtures covering onboarding, binding, routing, switching, estimates, and continuity behavior.

## Compatibility and updating from 1.0.1

This is a minor feature release, not a patch. Existing 1.x concepts and readable historical schemas remain available. Existing projects are not silently rewritten: obtain and verify the 1.1.0 package, keep the extracted framework outside the product repository, run onboarding against the current project, review the proposed external or pinned binding, and approve any migration before mutation. Historical sealed work-order schema 1.0 remains readable, but a new execution must migrate, be reapproved, and be resealed under the current contract rather than infer missing authorization.

## Known limitations and hardening triggers

- This release is not a formal security certification, immutable attestation, or general external-rollout approval.
- Provider/model capability evidence depends on the configured trusted host adapter or governed registry; universal provider detection is not claimed.
- Automatic model switching is not claimed where the host exposes only manual selection.
- Universal filesystem crash/power-loss durability and unvalidated platform support are not claimed.
- A dedicated Deep pre-release review remains required before distribution to general external users.
- Large dependency/model downloads, paid services, credentials, and cloud uploads require separate explicit authority.
